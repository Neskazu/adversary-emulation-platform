# Adversary Emulation Platform 🛡️

Платформа предназначена для автоматизированного развертывания лабораторной инфраструктуры, используемой для эмуляции действий злоумышленников (Adversary Emulation), тестирования средств обнаружения и проведения киберучений.

Проект разворачивает виртуальный стенд с помощью **Vagrant**, выполняет базовую настройку через **Ansible** и позволяет развертывать сценарии атак и правила детекции.

---

## 📋 Предварительные требования

Перед началом работы убедитесь, что у вас установлены:

* **Vagrant**
* **VirtualBox**
* **Ansible** (рекомендуется запускать из WSL или Linux)

---

## 🚀 Установка и запуск

Ниже приведена последовательность развертывания лабораторного стенда.

---

### 1. Настройка SSH-доступа 🔑

После запуска виртуальных машин Vagrant использует SSH-ключ для подключения к ним.
В данном проекте предполагается использование приватного ключа, который применяется Vagrant для доступа к ВМ.

#### Что это за ключ?

Vagrant по умолчанию использует так называемый *insecure private key* для первичного доступа к виртуальным машинам.
В вашем окружении этот ключ хранится в директории:

```
/mnt/s/vagrant_home/insecure_private_keys/vagrant.key.rsa
```

* `/mnt/s/` — примонтированный диск (например, в WSL)
* `vagrant_home` — директория с файлами окружения Vagrant
* `insecure_private_keys` — каталог с приватными ключами
* `vagrant.key.rsa` — приватный SSH-ключ

Если путь отличается — уточните расположение ключа в вашем окружении.

#### Копирование ключа в локальное SSH-хранилище

Создадим отдельную директорию для ключей лаборатории и установим корректные права доступа:

```bash
mkdir -p ~/.ssh/lab_keys
cp /mnt/s/vagrant_home/insecure_private_keys/vagrant.key.rsa ~/.ssh/lab_keys/id_rsa
chmod 600 ~/.ssh/lab_keys/id_rsa
```

* `mkdir -p` — создаёт директорию (если её нет)
* `cp` — копирует приватный ключ
* `chmod 600` — ограничивает доступ к ключу (требование SSH)

> ⚠️ Важно: приватные ключи не должны иметь открытых прав доступа.

---

### 2. Запуск виртуальных машин 📦

Инициализация и запуск виртуального окружения:

```bash
vagrant up
```

Команда создаёт и запускает виртуальные машины согласно конфигурации `Vagrantfile`.

Проверить статус можно командой:

```bash
vagrant status
```

---

### 3. Основная настройка (Provisioning) ⚙️

После запуска ВМ выполняется базовая конфигурация через Ansible.

> **Примечание:** Все команды ниже выполняются из директории `ansible`.

Перейдите в директорию:

```bash
cd ansible
```

Запуск основного плейбука:

```bash
ansible-playbook -i inventory.ini site.yml
```

Этот плейбук:

* выполняет базовую настройку хостов
* устанавливает необходимые компоненты
* подготавливает инфраструктуру к запуску сценариев

---

## ⚔️ Сценарии и атаки

После базовой настройки можно развернуть компоненты для проведения эмуляции атак и тестирования детектирования.

---

### Развертывание правил обнаружения (Detections) 🔍

Развёртывание правил детекции на SIEM-компоненты:

```bash
ANSIBLE_ROLES_PATH=./roles ansible-playbook -i inventory.ini playbooks/deploy-detections.yml --limit siems
```

Плейбук:

* загружает правила
* применяет их к соответствующим узлам
* активирует механизмы обнаружения

---

### Развертывание агентов Caldera 🕵️‍♂️

Установка и подключение агентов Caldera к C2-серверу:

```bash
ANSIBLE_ROLES_PATH=./roles ansible-playbook -i inventory.ini playbooks/deploy-caldera-agents.yml
```

После выполнения агенты регистрируются на сервере Caldera и готовы к выполнению сценариев.
